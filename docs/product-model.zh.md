# 产品形态 —— WebAgentFlow

> **本文是"WebAgentFlow 是什么"的权威文档**。
> AI 编码 Agent（Claude Code、Codex 等）在规划功能时**必须**以
> 本文为准。如果一个提议本文没覆盖，**停下来问**，不要擅自发明新
> 的角色 / 阶段 / 循环，再反向改代码去迁就它。
>
> 如果你对产品的理解变了，**先改这份文档**，再动代码。

---

## 1. 一句话

WebAgentFlow 代替用户在网页上敲键盘点鼠标：它先把页面学明白，然后
当用户提需求时，由系统自己开真实浏览器去完成 —— 而**不是**让大模型
在每一步去读 HTML、决定点哪里。

## 2. 页面的三个阶段

每个页面在 WebAgentFlow 的生命周期里都要经历 3 个阶段。功能归属
必须明确属于某一个阶段，**不要混淆**。

| # | 阶段 | 谁在开 | Phase 3 执行时大模型会不会逐步读 HTML？ |
|---|---|---|---|
| 1 | 自主学习 | 系统 | 是 —— 仅限学习阶段，有限使用 |
| 2 | 用户引导学习 | 用户（可视化浏览器里） | 否 —— 系统只是记录用户 |
| 3 | 实际工作 | 系统，基于学过的数据 | **否 —— 这是核心不变量** |

下面逐一展开每个阶段、涉及的 Agent，以及绝不能破坏的不变量。

---

## 3. Phase 1 · 自主学习

**触发**：系统第一次见到一个页面（或用户强制重新学习）。

### 3.1 流水线

顺序执行。每一步有清晰的输入/输出契约，组件可独立替换。

1. **取 HTML → Full AST**（服务端，`lxml`）。
   DOM 忠实转录；**不做语义改写**。
2. **Full AST → Simplified AST**（结构保留的投影）。
   Simplified AST 去噪但保留节点边界和兄弟顺序。它**不是**
   "页面摘要"。
3. **Agent A · 页面意图 Agent** 读 Simplified AST + 截图，写下
   这个页面是干什么的。
   - 输出：简短的页面用途描述，与 page signature 一起持久化。
   - 这是语义理解，不是可操作元素的抽取。
4. **代码**（纯确定性，无大模型）从页面提取可操作元素：
   fillable / submit / clickable / navigation / select / toggle。
   纯结构分类。
5. **代码**用 Playwright 尝试各种操作，并**把失败也记下来**。
   失败路径作为负面知识保留，不丢弃。
6. **Agent B · 尝试评估 Agent** 判定每次尝试的结果，标记异常。
   - 输出：单次尝试的 verdict + summary。和 Agent A 独立。
7. **Agent C · 学习报告 Agent** 把整个学习过程整理成给用户看
   的报告。
   - 输出：用户可读的报告（这个页面是什么、系统能干什么、有
     什么没搞定）。
8. **持久化**成一条学习过的页面记录：
   - page signature
   - 页面用途（来自 Agent A）
   - 可操作元素（来自第 4 步）
   - 成功路径（来自第 5 步，verdict=success）
   - 失败路径（来自第 5 步，verdict≠success）—— 作为负面知识
     保留，避免重复犯错。

### 3.2 Phase 1 刻意不是

- 不是 skill 注册表。学过的记录是一条按 page signature 归档的
  数据 blob，不是具名 skill。
- 不是一个大一统 Agent。Agent A / B / C 是**分开的**：不同 prompt、
  不同输出、不同失效模式。**不要合并**。
- 不是永久结论。支持重新学习。页面变了或用户纠正了，都可以重学。

---

## 4. Phase 2 · 用户引导学习

**触发**（任一）：

- 用户主动进入引导学习模式（给系统已经部分掌握的页面补数据）。
- 用户在 Phase 3 执行过程中**接管**（错误恢复或主动交接）。接管
  自动进入引导学习 —— 从那一刻起系统记录用户的所有操作。

### 4.1 流水线

1. 系统在**可视化**（非 headless）Playwright 浏览器里打开页面 ——
   用户在开。
2. 用户正常操作。
3. 系统记录每次交互：
   - 用了哪个 selector（从真实事件 target 反解）
   - 输入了什么 / 点了什么
   - 交互后可观测的状态变化
4. 记录的操作追加到页面的学习记录里，标 `provenance = user`。
   这些操作和 Phase 1 路径一起参与 Phase 3 的路径规划。

### 4.2 不变量

Phase 2 记录的是**用户真实操作**。
- **不**用大模型去推测用户意图。
- **不**事后改写用户做了什么。
- Provenance 永远保留，方便以后审查时信任数据来源。

---

## 5. Phase 3 · 实际工作

这才是终端用户关心的阶段。Phase 1 和 2 存在的唯一目的，是让
Phase 3 **便宜、快、可靠**。

**触发**：用户提需求（例如"登录 X 下载本周报表并保存为 CSV"）。

### 5.1 快乐路径

1. **Agent D · 规划 Agent** 读取：
   - 用户的任务描述
   - 目标页面的学习记录

   然后**选一条路线**。路线是一串具体动作（selector + 动作类型 +
   值），从学过的路径里选出来。

   Agent D **绝不读原始 HTML**。它只读学过的数据。它的工作是
   "从已验证的路径里挑正确那条"，**不是**"从零开始想要点哪里"。

2. **代码**用 Playwright 执行所选路线。
   - Selector / 值 / 动作类型完全确定 —— 来自学习数据，不是
     大模型在循环里做的决定。
   - 每个动作的观测（URL 前后、DOM 信号等）记录下来给报告 Agent。

3. **Agent E · 结果报告 Agent** 把结果总结给用户。
   输出：自然语言结果 + UI 可渲染的结构化字段。

### 5.2 核心不变量

Phase 3 执行过程中，**大模型只在边界处介入** —— 开始时规划，
结束时报告，出错或中断时对话。
它**绝不**被调用来决定下一次点击、下一次按键、填哪个字段，因为
这些决定已经编码在学习记录里。

**这一条不可商量**。这就是 WebAgentFlow 跟"大模型盯着浏览器乱点"
的根本区别。破坏这一条，你就做的是另一个产品了。

### 5.3 错误处理

动作失败时（页面报错、找不到元素、可观测状态没变化、5xx 等等）：

1. 执行**暂停**。**绝不**偷偷重试。
2. **Agent F · 恢复对话 Agent** 开一个和用户的对话：
   - 发生了什么
   - 哪一步失败了
   - 系统认为有哪些选项
3. 基于用户回复，系统三选一：
   - **重新规划继续**：Agent D 根据新上下文重新选一条路线，继续。
   - **从头重跑**：用于部分状态不安全时。
   - **交给用户**：进入 Phase 2。用户手动完成任务，动作被记录、
     反哺学习记录。

### 5.4 用户主动中断

用户可以随时停止运行。停下时：

1. 执行立刻暂停。
2. **Agent G · 中断对话 Agent** 开对话：
   - 目前做了什么
   - 页面处于什么状态
   - 用户想怎么办（继续 / 重跑 / 交接 / 放弃）
3. 系统按用户回复执行。

中断和错误**不是一回事**：中断是用户在一次原本正常的运行上主动
介入。不同 Agent、不同 prompt、不同语气。

## 6. Agent 总表（单一权威）

这些是**独立**的 Agent。不要合并。不同 prompt、不同输入、不同输出、
未来会用不同的模型。

| ID | 名称 | 阶段 | 读什么 | 产出什么 |
|---|---|---|---|---|
| A | 页面意图 | 1 | Simplified AST + 截图 | 页面用途描述 |
| B | 尝试评估 | 1 | 尝试日志 + 前后状态 | 单次尝试的 verdict + 异常 |
| C | 学习报告 | 1 | 整个学习过程 | 给用户看的学习报告 |
| D | 规划 | 3 | 用户任务 + 学习记录 | 选定的具体路线 |
| E | 结果报告 | 3 | 执行结果 | 给用户看的结果 |
| F | 恢复对话 | 3（错误） | 错误上下文 + 近期步骤 | 对话记录 + 下一步动作 |
| G | 中断对话 | 3（用户中断） | 当前状态 + 中断信号 | 对话记录 + 下一步动作 |

加新能力时先问：**这属于哪个 Agent？** 如果答案是"新的一个"，那
是产品级决策，**先更新本文档**再写代码。

## 7. 跨阶段不变量

跨所有阶段都适用。违反就是产品 bug，不是实现细节。

1. **Phase 3 执行过程中，大模型永远不在逐步循环里。** 只在规划 /
   报告 / 对话三处出现。
2. **失败是数据。** Phase 1 失败的尝试要持久化，不能丢。
3. **Provenance 永远保留。** 每个学过的动作都知道自己来自 Phase 1
   （系统）还是 Phase 2（用户）。
4. **允许重新学习。** 页面漂移了可以重学，系统不能假定学到的东西
   永久有效。
5. **绝不偷偷重试。** 错误触发对话，不触发隐藏的重试循环。
6. **学习路径和执行路径是两条代码路径。** 用 Phase 1 的编排器去跑
   Phase 3 的任务是坏味道；Phase 3 应该是**无聊的、确定的**。

## 8. 当前代码库所处位置

诚实对照，让"愿景 vs 现实"的差距显性化。阶段落地了就更新这段。

- **Phase 1 步骤 1–2（HTML → AST → Simplified AST）**：录制 /
  扩展侧的路径已经有了；自主探索当前用的是实时页面分析器
  （`page_analyzer.py`），不是离线 AST 管线。两条路径的统一是待做项。
- **Phase 1 步骤 3（页面意图 Agent）**：**尚未**单独做成一个
  Agent。今天的 Supervisor 把"理解意图"和"评估结果"混在一起了。
- **Phase 1 步骤 4–5（元素抽取 + 尝试）**：已交付（在自主探索
  子系统里）。
- **Phase 1 步骤 6–8（评估 + 报告 + 持久化）**：部分完成 —— verdict
  有了、报告有了，但**"落成学习路径"还没做**。当前 run 被写入
  `exploration_runs` 只是跑过历史，不是学到的路径。
- **Phase 2（用户引导学习）**：未开工。扩展在录事件，但还没有
  "把用户操作追加到学习记录"的引导模式。
- **Phase 3（实际工作）**：未开工。没有规划 Agent、没有重放、
  没有恢复对话。**这是下一个大目标**。

某个阶段完整落地后，回来更新本段。
