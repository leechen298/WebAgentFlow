## What M10 Completed

M10 · Path Asset Foundation

M10 turns learned operations into reusable path assets.

Completed scope:

- LearnedPath persistence: `pass_gate = pass` runs can be persisted as reusable
  LearnedPath records.
- LearnedPath catalog: operators can inspect learned paths, source runs,
  stored actions, and path-level trust state.
- Replay execution foundation: an existing LearnedPath can be replayed
  deterministically against a provided URL.
- Drift / flaky / deprecated / trust signal: replay and catalog flows expose
  page mismatch, signature change, missing target, unsupported action, flaky,
  deprecated, provisional, and confirmed states as reviewable signals.
- Replay-related tests and evidence: replay API, catalog replay UI,
  deterministic E2E, and exploratory evidence are recorded under M10 testing
  docs.

M10 does not make WebAgentFlow an arbitrary task runner. It creates the
LearnedPath asset foundation that M11 can safely retrieve, plan from, and
execute through replay.

## What M11 Completed

M11 · Runtime Conversation, Task-to-Path, and Runtime Chat MVP

M11 connects user task input to learned path selection, preview, confirmation,
replay execution, evidence-bound reporting, and the first product-facing
`wagent chat` runtime behavior gates.

### M11.0

M11.0 completed the runtime conversation foundation:

- conversation domain / state contract.
- session / message / event store.
- Conversation API.
- runtime CLI shell: `wagent conversation`.
- Conversation Orchestrator / Dispatcher.
- explicit `/replay <learned_path_id> <url>` hook.
- conversation tests and evidence.

M11.0 created the runtime entry where the user talks to WebAgentFlow, while
keeping the old `wagent verify` / `verify-scenario` development verification
surface separate.

### M11.1

M11.1 completed the first task-to-path MVP chain:

- 11.1.1 Task Planning Domain Contract.
- 11.1.2 LearnedPath Retrieval and Ranking.
- 11.1.3 Task Path Planner MVP.
- 11.1.4 Task Planning Dispatch Preview.
- 11.1.5 Plan Confirmation and Consent Gate.
- 11.1.6 Execution via Replay.
- 11.1.7 Result Verification and Task Result Reporter.
- 11.1.8 Task-to-path Tests and Evidence.

The completed chain is:

```text
record / learn operations
-> persist as LearnedPath
-> user submits natural-language task
-> LearnedPath retrieval / ranking
-> Task Path Planner
-> planning preview
-> user confirm / cancel / reject
-> confirmed plan executes through replay
-> Task Result Reporter reports from evidence
-> tests and evidence closure
```

Core safety boundaries are part of the shipped MVP:

- replay completed != task succeeded.
- no postcondition evidence -> `uncertain` / `needs_review`.
- `failed` / `blocked` does not automatically trigger recovery.
- no hidden relearning.
- no autonomous run.
- no raw HTML planner.
- no default LLM provider dependency for task-to-path execution.

## Current Capability Boundary

Current v0.1 can:

- record / learn operation paths through the existing learning flow.
- persist successful learned paths as LearnedPath assets.
- search and rank existing LearnedPaths for a user task.
- generate a task-to-path planning preview.
- wait for explicit user confirmation.
- execute a confirmed single-path plan through deterministic replay.
- generate an evidence-bound Task Result Reporter output.
- let a user interact with the first-wave `wagent chat` runtime behavior gates:
  URL-only known / unknown, execute-known, execute-unknown guidance,
  unknown choose-learn, execute-unknown choose learning flow, and vague input
  no execution.
- return `uncertain` / `needs_review` when there is no verification evidence.
- return `failed` / `blocked` without silently retrying, recovering, or
  relearning.

Current v0.1 does not represent:

- arbitrary web autonomous exploration for every task.
- arbitrary task completion.
- automatic creation of new paths during task execution.
- full learn-then-execute.
- page-wide automatic capability discovery.
- automatic learning of every operation on a page.
- mature broad-domain slot binding.
- mature postcondition verification.
- automatic recovery.
- teaching mode.
- LLM-driven free planning or step-by-step browser control.
- external black-box site validation.

## Known Limitations

- Initial parameterized value-slot replay exists for the current runtime path,
  but mature binding of names, dates, statuses, export formats, and other task
  terms into learned action values remains future scope.
- Runtime Observation / Wait-for-change has scoped M11.2 support, but it is not
  implemented as a complete cross-site capability.
- Real webpage issues such as popups, modals, toasts, loading states, and async
  updates still need later hardening beyond the current scoped M11.2 work.
- Network-triggered partial refresh, delayed button enablement, and SPA content
  changes are not systematized.
- Result verification is conservative. When postcondition evidence is missing,
  the result is `uncertain` / `needs_review`, not success.
- Recovery / abort / retry / user interruption belongs to v0.2 / M12.
- Teaching mode belongs to a later stage.
- Full learn-then-execute remains a follow-up after 11.3.7.
- Page-wide automatic capability discovery and batch learning of all page
  operations remain follow-up work.
- External target source pages and scenario catalogs stay outside this
  repository; WebAgentFlow consumes runtime inputs and result evidence only.
