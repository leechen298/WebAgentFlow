# Scope Boundaries — What's Explicitly Out of Scope

This document lists capabilities that are **deliberately not** part of the
current delivery milestone. When in doubt, check here before proposing or
implementing them. Items on this list are deferred until a prerequisite
milestone validates.

For **what the product is** (the L1/L2/L3 lifecycle model and the Agents),
see [`product-model.md`](./product-model.md). If a proposal isn't
in that document AND isn't listed here as out-of-scope, pause and
ask — don't invent.

## Current Delivery Milestone

M10.2 has completed. The next planned delivery package is
**M11.0 · Runtime Conversation Shell & Agent Orchestration**.

Until the M11.0 iteration documents are written, this file keeps the
last completed M10.2 boundaries as historical reference and the roadmap
as the source for the next milestone. Iteration documents live under
`docs/iterations/m<N>/`; planning language uses M<N> for delivery
milestones and L1/L2/L3 for lifecycle stages.

Last completed package: `10.2-replay-execution-drift-detection`.
M10.2 implemented LearnedPath replay plus drift detection:

- consume an existing LearnedPath from the catalog
- replay its stored actions against a provided URL
- return replay status, step logs, and drift reasons such as page
  mismatch, signature changed, `target_missing`, or
  `unsupported_action`

M10.2 is not an L3 task runner. Replay / drift results may become a
future source of failure evidence and drift evidence, but this package
did not implement the complete negative-knowledge store.

## Not in Scope

### Execution & Orchestration

- **Runtime conversation CLI** — not M10.2. There are three different
  CLI surfaces:
  - current `wagent verify` / `verify-scenario`: a development
    verification skill backend that already exists for auditable
    scenario checks;
  - M11.0 Runtime Conversation CLI: the future runtime product entry
    where the user talks to WebAgentFlow;
  - M16 External CLI: the later stable tooling surface for external
    schedulers, scripting, and integration.
  Only the existing `verify-scenario` backend is present during M10.2;
  the M11.0 and M16 CLIs are outside this package.
- **Skill / Tool interface for third-party Agents** — the public
  interface is still the HTTP API. The one exception is the
  `verify-scenario` Claude Code skill (generated by the `wagent`
  CLI via `wagent skill install` into `~/.claude/skills/`), which
  wraps the same HTTP endpoint with an auditable reporting contract
  so an AI coding agent can run scenarios without bypassing the
  Supervisor Agent. A broader registry for third-party Agents is
  still a later milestone.
- **Task-to-Path Planning MVP** — user task / chat input, Agent D Path
  Planner, path retrieval / ranking, slot binding, execution
  confirmation, task result verification, and Agent E result reporting
  are M11.1, not M10.2.
- **Recovery / abort dialogue** — Agent F Recovery Dialogue and Agent G
  Abort Dialogue are M12, not M10.2.
- **Agent H Teaching Guide Agent** — guided teaching belongs to M13, not
  M10.2.
- **Runtime Agent orchestration** — M10.2 does not implement Agent
  D / E / F / G / H, a session controller, pause / resume / abort
  commands, takeover routing, or user-facing runtime conversation.
- **Multi-page workflow composition** — composing multiple LearnedPaths
  into a cross-page workflow is M17, not M10.2.
- **Action risk & consent gate** — risk classification, destructive
  action interception, user-defined risk policy, and pre-execution
  consent gates belong to M11 / M12 follow-up work. They are not part
  of M10.2.

### Supervision

- **Real-time per-step LLM supervision in L3** — LLMs may participate at
  planning, reporting, recovery / abort dialogue, or user-teaching /
  handoff boundaries only. They must not decide browser actions step by
  step during L3 execution.
- **External AI-coding-agent supervision** — the AI coding tool (Claude Code,
  Codex, …) must not act as supervisor. See `CLAUDE.md` §
  "AI Coding Agent — Execution Boundary".

### Learning & Abstraction

- **User-guided learning and correction** — visible-browser takeover,
  real user-action recording, provenance write-back, and path correction
  are M13.
- **Guided teaching mode** — guided teaching, element highlight,
  indicator / tooltip overlays, and Teaching Guide Agent interaction
  are M13. M10.2 does not build a visible-browser teaching overlay and
  does not record real user operations.
- **Control coverage expansion and pattern mining** — popup controls,
  custom click-toggle controls, additional label handlers, and
  cross-page pattern mining are M14 unless explicitly reprioritized.
- **Learning Reporter product surface** — Agent C's user-facing learning
  report is M14. Current workbench/history output is developer-oriented
  evidence, not the final Agent C report.
- **Negative knowledge store** — formal assetization of failed attempts,
  replay drift, `target_missing`, `unsupported_action`, and user
  corrections is M14 / M15. M10.2 may emit replay / drift evidence, but
  it does not implement the full store.

### Parser / AST

- **"Page summarizer" approaches that restructure DOM for readability** — the
  AST layer must preserve structural fidelity. Summarization, if needed, is a
  separate downstream view.
- **Simplified AST with semantic restructuring** — the Simplified AST is a
  structure-preserving projection, not a rewrite.

### Data / Persistence

- **Full external interface suite** — stable API / CLI / Skill / Tool
  surfaces for external schedulers are M16.
- **Target-site authority / session boundary** — the default assumption
  is that the WebAgentFlow operator already has permission to operate
  the target website. Cookies, `localStorage`, session state, and
  target-site permissions are owned by the operator and the target
  website. Session expiry, permission denial, target-site auth redirects,
  and operation failures are runtime failure / recovery issues.
- **Artifact lifecycle** — download / export / upload / screenshot
  artifact capture, storage, display / return, retention, and cleanup
  are later M11 / M15 / M16 / M18 work. M10.2 only returns replay
  result data and auditable status.
- **Engine data hygiene** — retention, cleanup, redaction, and audit
  policy for logs, screenshots, artifacts, conversation records, and
  LLM prompt payloads are later hygiene work, not M10.2.
- **Autonomous-run result persistence** — SHIPPED. Every autonomous run
  is written to `exploration_runs` with
  `strategy_json.kind == "autonomous"`. List + detail via
  `GET /exploration/autonomous-runs[/{run_id}]`, filterable by `spec_id`
  and `scenario`.
- **LearnedPath write-back** — SHIPPED in M10.1 for `pass_gate = pass`
  autonomous runs. Further write-back from user-guided learning belongs
  to M13.
## Re-evaluation Triggers

Open this list whenever:

- A milestone completes and you're asking "what's next?" — check prerequisites
  and entry criteria for deferred items.
- A user asks for a feature that "feels obvious" but isn't in the codebase —
  it's probably deliberately deferred.
- Working on a feature that seems to require one of these — consider whether
  a smaller alternative would unblock the current milestone without pulling in
  the deferred work.
